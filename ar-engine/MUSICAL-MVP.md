# 실사 AR 뮤지컬 MVP 실행 안내

새 공연은 `?musical=1`로 연다. 기존 화면의 **③ 실사 AR 뮤지컬 MVP**에서도 진입한다. 종료하면 기존 별의 새싹·외벽 정합 화면으로 돌아간다. 기존 AR 엔진, 원래 GLB·애니메이션, 스테이징 스크립트, 패키지·잠금파일, Vite·배포 설정은 유지했다. HTML의 모듈 진입점만 추가 라우터로 연결했다.

공간형 공연자 강화 구현은 [SPATIAL-PERFORMERS.md](./SPATIAL-PERFORMERS.md)를 참고한다. 두 실사 영상 평면은 건물 앵커 아래의 고정된 공간 객체이며, 같은 슬롯에 시간별 비평면 GLB 캡처 시퀀스를 불러올 수 있다. 실제 사람의 볼류메트릭 촬영본은 미제공이므로 입체 로더는 명확히 구분한 비인물 도형으로 검증한다.

## 실행

기존 명령 그대로 사용할 수 있다.

```powershell
cd ar-engine
npm run dev
```

동일 Wi-Fi의 스마트폰에서 출력된 **HTTPS Network URL에 `?musical=1`**을 붙여 연다. iPhone은 Safari, Android는 Chrome을 우선 대상으로 한다. 개발용 자체 서명 인증서는 기기에서 신뢰해야 하며 `secure=true` 상태를 확인한다. 기존 서버와 별도로 검증 서버를 실행한 경우 포트는 5187이다.

## 현재 구현 범위

| 항목 | 구현 |
| --- | --- |
| 사진 기반 무대 | 목재 격자·문·기둥·가로 프레임·산수화 패널을 개별 Three.js 구성요소로 생성 |
| 치수 | `musical-assets/show.json`에서 관리, 전부 미실측 임시값 |
| 건물 가림 | 렌더링 모델과 별도인 기둥 depth-only 모델. 기본 비활성 |
| 공통 AR | MindAR 이미지 표적의 위치·방향 추정. 표적을 놓치면 숨김·일시정지 |
| Android 추가 AR | 기존 PlacementGroup·Reticle 규칙을 재사용한 WebXR 바닥 배치·수동 정합 |
| 실사 영상 | 배우별 로컬 파일, H.264 MP4 컬러/알파 패킹·네이티브 알파·녹색 크로마키 |
| 공연 | 30초 데이터 타임라인, 두 배우의 등장·퇴장, 무대 조명, 제한된 파티클 |
| 음향·동기 | 하나의 AudioContext 시계, 영상 드리프트 보정, 음악 교체·일시정지·재개·다시 보기 |
| 실패 처리 | 로드·재생 준비 시간 초과, 디코딩·재생 거부, 지속 버퍼링, 추적 상실·페이지 비표시에서 정지 |
| 개발자 제어 | 무대/배우별 위치·회전·크기, 모델·가림 표시, 로컬 정합 저장·복원·초기화 |
| 사진 | 공통 이미지 추적 경로에서 실경+장면 합성 PNG. WebXR는 OS 캡처 안내 |

프로젝트 공연자의 촬영본은 아직 제공되지 않았다. 대신 Pexels 공식 사용 조건을 확인한 **실제 사람의 춤 영상 2개**를 10초·무음·알파 패킹 MP4로 가공하여 포함했다. **실사 샘플 배우 2명 불러오기**를 누르면 직접 촬영한 영상 없이 움직이는 사람으로 시연할 수 있다. 제작자는 Yoshi Mura와 SERGEY ZIMA이며 출처·변형·사용 조건은 [MEDIA-CREDITS.md](./musical-assets/MEDIA-CREDITS.md)에 기록했다. 캐릭터나 정지 사진을 실제 공연자로 표시하지 않는다.

미디어를 선택하거나 샘플을 불러오기 전에는 **실사 공연 시작이 비활성**이고 명확히 구분한 카드·조명 테스트만 실행할 수 있다. 테스트 음악은 코드로 생성한 음원이다. 스톡의 원래 안무와 맞춰 제작한 완성 뮤지컬은 아니며, 샘플 B는 발 아래가 원본 프레임 밖인 구도다. 샘플 키잉의 경계·그림자는 최종 촬영본의 깨끗한 알파와 차이가 있다. 개발 미리보기는 카메라 AR이 아니며 화면에도 그렇게 표시한다.

## 스마트폰 시연 순서

1. **실사 샘플 배우 2명 불러오기**를 누르거나 아래 조건에 맞는 두 배우의 영상을 선택한다. 직접 촬영한 영상은 각 배우의 파일과 배경 처리 방식을 지정한다. 실제 음원을 선택하려면 30초 이상 파일을 사용한다.
2. 실행 경로에서 **공통 이미지 표적 추적**을 선택한다. 기본 표적은 사진 2의 산수화 패널을 원근 보정한 이미지다. 미리 생성된 `panel.mind`가 포함되어 휴대폰에서 컴파일하지 않아도 된다.
3. 실제 패널 너비를 입력한다. 기본 1.55m는 임시값이다. 패널을 정면에 가깝게, 충분한 조명에서 비춘다. 전체 벽이나 반복 격자만 비추지 않는다.
4. 카메라를 시작한다. 표적을 찾으면 자동으로 보이는 정합 모델과 실물의 기둥·산수화·문 위치를 개발자 패널에서 맞춘다. **정합 확정**하면 모델이 숨고 실경 위에 배우와 효과가 표시된다. 필요하면 모델 표시를 다시 켤 수 있다.
5. **정합 확정 → 공연 시작**을 누른다. 5초에 A, 10초에 B가 등장하고 20초에 절정, 27초에 피날레, 30초에 종료된다.
6. 천천히 좌우 이동하여 무대가 표적과 함께 같은 실제 위치에 유지되는지 확인한다. 표적을 벗어나면 공연이 숨고 멈춰야 한다. 표적이 복귀해도 음원은 자동 재개하지 않는다.
7. 일시정지·재개·다시 보기를 시험한다. 사진은 공통 경로에서만 앱 내 합성을 지원한다.

기본 산수화 패널은 저대비이고 사진의 원근 보정도 임시이므로 실제 인식률이 충분하지 않을 수 있다. 작은 표적으로는 시뮬레이션에서도 인식이 실패했다. 먼저 패널을 화면에 크게 담아 인식을 확인하고, 두 배우가 함께 보이도록 가로 화면에서 구도를 조정한다. 필요하면 개발자 모드로 배우 간격도 맞춘다. 인식이 어려우면 현장에서 **평평한 패널만 정면 촬영한 사진**을 선택하여 표적을 준비한다. PC에서 `.mind`를 저장한 뒤 휴대폰으로 불러올 수도 있다. 사용자 사진을 서버로 전송하지 않는다. 물리적으로 평면인 인식 대상이 필요하며 사진 속 공간 전체를 단일 평면으로 가정하면 안 된다.

## 영상 형식

권장 파일은 **좌측 RGB 영상, 우측 흑백 알파**를 같은 프레임에 넣은 H.264 MP4다. 흰 알파는 불투명, 검정은 투명이다. 일반 MP4 자체에 알파 채널이 있다고 가정하지 않는다. 네이티브 WebM/HEVC 알파는 기기별 디코더 차이 때문에 별도 시험한다. 배우 오디오는 음소거하고 음악 파일을 공통 시계로 사용한다. 짧은 배우 클립은 현재 데이터의 `loop: true`에 따라 반복한다.

투명 원본을 보유한 경우:

```powershell
.\scripts\prepare-performer.ps1 -InputVideo 'D:\공연\actor-a-alpha.mov' -OutputVideo 'D:\공연\actor-a-packed.mp4'
```

RGB와 같은 길이·편집의 흑백 매트가 따로 있는 경우:

```powershell
.\scripts\prepare-performer.ps1 -InputVideo 'D:\공연\actor-b-color.mp4' -MatteVideo 'D:\공연\actor-b-matte.mp4' -OutputVideo 'D:\공연\actor-b-packed.mp4'
```

FFmpeg가 PATH에 있어야 한다. 스크립트는 원본을 덮어쓰지 않으며 배경을 자동 제거하는 도구는 아니다. 녹색 배경 원본은 크로마키 모드를 선택할 수 있다. 실제 제작본의 해상도는 우선 배우당 RGB 360×640 또는 480×720, 24fps 정도로 시작하여 2개 동시 디코딩을 측정한다. 권리·출연 동의가 확인된 파일을 사용한다.

영상 평면은 무대 좌표에 고정되며 카메라를 따라 도는 빌보드가 아니다. 측면에서 얇아지고 뒷면에서 좌우가 반대로 보일 수 있다. 이것은 볼류메트릭 비디오가 아니다. `PerformerRenderer` 인터페이스와 고정된 `PerformerSlot`을 통해 동적 3D 메시 시퀀스 로더로 교체할 수 있다. 실제 인물 3D 캡처는 아직 미제공이다.

## 좌표와 기존 구현의 관계

무대는 기존과 같이 미터, Y-up, 정면 -Z다. 같은 `PlacementGroup`으로 외곽 정합을 분리한다. 이미지 추적 어댑터가 픽셀 단위/+Z 표적 좌표를 미터/-Z 무대 좌표로 변환한다. 원점은 무대 하단 중앙이며 기본 표적의 중심은 `building.target.center`다. `door`·`panel` 앵커를 각 배우의 부모로 두어 배우 위치는 건물 로컬 오프셋으로 관리한다.

이미지 추적은 표적이 보이는 동안 6DoF 포즈를 추정한다. 표적 밖에서도 유지되는 ARKit/ARCore SLAM이나 GPS 고정이라고 표시하지 않는다. iPhone의 기존 Quick Look 경로는 그대로이며 **새 실시간 영상 공연을 Quick Look으로 내보내지 않는다.** 브라우저 영상·알파 셰이더·음원 제어는 새로운 공통 이미지 추적 경로가 담당한다. [MindAR 원본 문서](https://hiukim.github.io/mind-ar-js-doc/quick-start/overview/)

Android WebXR 공연 경로는 hit-test+local-floor/local 참조 공간을 사용한다. 바닥 링을 탭한 후 수동으로 벽 위치에 맞춘다. 원래 엔진과 마찬가지로 XRAnchor API를 생성하지 않는 참조 공간의 월드 배치이며, 실제 벽 자동 인식을 주장하지 않는다. 공연 종료 후 원래 AR로 복귀하면 새 세션·배치가 필요하다.

정합 저장은 표적 해시·건물·표적 너비를 포함한 신규 키를 쓴다. 무대의 로컬 보정과 배우 오프셋만 저장하며, 카메라 월드 좌표를 영속 앵커로 저장하지 않는다. 기존 `ar-calib:*` 키에는 쓰지 않는다.

## 자동 검사와 실기기 검증 구분

```powershell
npm run typecheck
node tests/musical-unit.mjs
node tests/spatial-volume-unit.mjs
npm run verify:asset
npm run verify:alignment
npm run build
```

별도 브라우저 검사는 기존 의존성을 변경하지 않는 임시 Playwright 설치를 사용한다.

```powershell
npm install --prefix ../.tmp/musical-qa --no-package-lock --no-audit --no-fund playwright@1.56.1
node tests/musical-browser.mjs
node tests/spatial-volume-browser.mjs
```

기본 검사 URL은 `https://localhost:5187/`이며 첫 번째 명령 인자 또는 `MUSICAL_TEST_URL`로 바꿀 수 있다. 브라우저 검사는 실제 WebGL 표적 컴파일과 이미지 인식, 합성 카메라에서 표적 상실, 30초 재생, 두 개의 **비인물 테스트 MP4** 및 두 실사 스톡 샘플의 디코딩을 검증한다. 이는 iPhone·Android 실제 카메라나 현장 공연자의 검증이 아니다.

## 현장 합격 기록

| 항목 | 합격 조건 | 현재 기록 |
