# 실행용 웹 SLAM 공연 배포

실행 주소: **https://ar.lobodoc.com/?musical=1&v=world1**

기본 공연 경로를 설치 없는 웹 SLAM으로 바꿨다. 페이지에 포함된 실사 샘플 2명이 자동 준비되며 **카메라 시작 → 바닥을 천천히 비춤 → 무대 중심 탭 → 공연 시작** 순서다. 산수화 표적 사진은 필요 없다. 기존 이미지 경로는 `?musical=1&tracking=image`, 기존 별의 새싹·외벽 Quick Look/WebXR는 루트 화면에 남아 있다. GPS 장소 해금은 기존 계약대로 외부 셸 담당이다. GPS로 벽의 정확한 정합을 완료했다고 표시하지 않는다.

## 실제 구현

8th Wall XR Engine의 배포용 바이너리 `@8thwall/engine-binary@1.0.0`을 자체 서버에 원본 그대로 포함했다. SLAM을 포함하지 않는 MIT 프레임워크와 구별한다. 최신 배포·자체 호스팅 지원을 확인하여, 이전의 “iPhone 표적 없는 공연은 네이티브 앱이 필수”라는 설명을 정정한다. [공식 엔진 배포 설명](https://8thwall.org/docs/open-source), [공식 Three.js 연동](https://8thwall.org/docs/engine/overview).

`src/musical/slam.ts`가 SDK의 6DoF 포즈 상태와 3D hit-test 결과를 사용한다. 추적이 NORMAL이고 유효한 3D 지점이 반환될 때만 배치한다. 카메라 자식이나 고정 거리의 가짜 앵커를 사용하지 않는다. 같은 Three.js 무대·PerformerSlot·영상·30초 타임라인을 재사용한다. 한 번 배치한 무대는 카메라 이동에 따라 다시 배치하지 않는다. 추적 상실·갱신 정지·백그라운드에서 무대를 숨기고 재생을 멈춘다. 복구 후 자동 재생하지 않는다.

SDK는 하나의 바닥 평면을 추정한다. 사진 매칭은 없지만 무늬가 전혀 없는 바닥·빠른 이동·반사광에서는 SLAM도 불안정할 수 있다. 자동 건물 인식·VPS·영속 장소 앵커는 아니다. 초기 방향/크기는 개발자 정합에서 조절한다. 배우는 공간 고정 영상 평면이며 완전한 볼류메트릭 인물이 아니다.

실경과 Three.js를 같은 SDK 캔버스에 그려 사진을 저장한다. 실제 아이폰에서 좌우/전후 이동·발 위치·사진 포함·음원 지연·발열을 확인해야 한다.

## 검증 구분

- 타입 검사·표준 빌드·기존 파일 38개 보호 검사 통과.
- 기존 이미지 경로: 30초 재생·두 실사 영상·사진·추적 상실/복구 및 기존 iPhone UA의 USDZ 링크 회귀 검사 통과. 한 번의 동시 소프트웨어 GPU 부하 시험에서 영상 지연으로 중단되었고, 실제 SDK 부하 시험과 분리한 재검사에서 통과했다.
- [실제 SDK 런타임 검사](./runtime-probe.json): 배포용 엔진을 실제로 로드해 Three.js/카메라 파이프라인을 시작한다. 입력은 데스크톱의 합성 카메라로, 추적 LIMITED를 성공으로 올려 쓰지 않는다.
- [어댑터 계약 검사](./adapter-report.json): SDK 공개 API를 **모의 구현**해 미추적/지점 없음에서 배치 차단, 배치 후 두 영상 재생, 추적 상실 정지와 자동 재개 방지를 확인한다. 실제 SLAM 성능 시험이 아니다.
- **실제 iPhone·Android의 이동 공간 고정은 아직 미검증**이다. 배포 성공·합성 카메라·모의 SDK를 실기기 합격으로 보고하지 않는다.

## 빌드와 배포

```powershell
cd ar-engine
node scripts/stage-web-slam.mjs
npm run build
```

SDK 원본은 `vendor/xr8`에 있고 추가 스테이징 도구가 `.assets/xr8`에 복사한다. 기존 `stage-assets.mjs`, 패키지/잠금파일과 Vite 설정은 수정하지 않는다. 기존 스테이징은 5개 모델 파일을 유지하고 새 SDK 폴더를 제거하지 않는다. 바이너리를 수정·번들 변형하지 않는다. 저작권·라이선스·무보증 고지와 SDK-MANIFEST.json을 배포에 포함하며 UI의 개발자 패널에서 라이선스로 연결한다.

배포 이미지 `ar-site:musical-13b3b704`, 이전 이미지 `ar-site:rollback-20261029T170817Z`. 배포 ZIP은 웹 실행 파일 46개를 포함하며 SHA-256은 `13b3b704fecb0d7bb3ceff6152da8dc429a0b2f75c8eec4f02a4b3b34827528f`다. 호스트 HTTPS/nginx·기존 Docker 구성 파일은 변경하지 않았다.
