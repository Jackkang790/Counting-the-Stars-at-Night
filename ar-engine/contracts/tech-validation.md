# 기술 검증 항목 (실기기 검증 전까지 "완료" 아님)

> 상태: **초안(DRAFT)**
> WebXR **기본 기능으로 보장되지 않는** 항목을 별도로 관리합니다.
> 지원되지 않는 기능을 **가짜 AR 효과로 대체하지 않으며**, 실제 공간 인식이
> 구현된 것처럼 보고하지 않습니다.

## 상태 표기
`PLANNED(구상)` · `IMPLEMENTED·UNVERIFIED(구현됨, 미검증)` · `VERIFIED(실기기 검증됨)` · `BLOCKED(차단)`

## 요구사항 분류 (구현 가능 / 추가 검증 / 자료 부족)

| 기능 | 판정 | 근거 |
| --- | --- | --- |
| 바닥 평면 인식 + 모델 배치 (04-A) | **구현 가능** | WebXR Hit Test 표준 기능 |
| 솟아오름 애니메이션 / 터치 상호작용 | **구현 가능** | glTF 애니메이션 + raycast |
| 카메라 이동 시 위치 유지 | **구현 가능** | WebXR anchors 또는 world-space 고정 |
| 담장(수직면) 작품 배치 (04-C) | **추가 검증** | 수직 평면 인식은 기기·Chrome 버전별 편차 (TV-02) |
| 실제 건물과 가상 콘텐츠 정렬 (04-B) | **추가 검증** | WebXR에 건물 인식·정합 기본 기능 없음 (TV-03) |
| 건물 자동 식별(비추면 자동 판별, 03) | **추가 검증** | 객체/건물 인식 기능 없음 → 기준 이미지·마커·수동 필요 (TV-01) |
| 과거 복원 합성 (04-B) | **구현 가능(정렬 의존)** | 렌더링은 가능하나 정확도는 TV-03에 종속 |
| 역할극 벽 투시 연출 (06) | **구현 가능(가상 합성)** | 실제 투시 아님. 포털/합성으로 구현 (TV-04) |
| 광원 추정 | **추가 검증** | light-estimation 미지원 기기 존재 (TV-05) |
| 실기기 성능 | **추가 검증** | 중급 Android 성능 예산 확인 (TV-06) |
| 브라우저/기기 호환성 | **추가 검증** | 실제 매트릭스 측정 필요 (TV-07) |

> **자료 부족**: 에피소드 건물 3곳의 **기준 이미지/마커/스팟별 앵커 데이터**,
> 역할극 대본, 작가·작품 목록(와이어프레임 "확정 필요"). 아래 TV-01/03에 영향.

## TV-01 — 건물/빈 땅/담장 자동 판별 (03 자동 인식)
- **가설**: "비추기만 하면 자동 판별"은 WebXR 기본으로 불가.
- **현실**: WebXR에 장면 분류/객체 인식 없음. Hit Test는 평면의 **위치·방향**만 제공.
- **접근(단계적)**:
  1. 평면 **방향 힌트**(수평=바닥/빈 땅 후보, 수직=담장 후보) 자동 추출.
  2. 최종 체험 종류는 **카탈로그(buildingId/spotId/experienceId)** 로 외부가 지정(= 사실상 확정).
  3. 완전 자동 판별은 범위 밖으로 둠(필요 시 별도 SDK 검토).
- **통과 기준**: 수평/수직 평면을 90% 이상 올바르게 힌트. 자동 "건물 식별" 주장하지 않음.
- **상태**: `PLANNED`

## TV-02 — 수직 평면(담장) 인식·추적 (04-C)
- **가설**: 담장·벽면에 작품 패널을 밀착 배치·유지 가능.
- **리스크**: 수직 평면 Hit Test는 기기/Chrome ARCore 버전·텍스처 유무에 민감.
- **접근**: 수직 Hit Test 우선, 실패 시 **수동 벽면 지정**(사용자가 벽을 향해 탭) 폴백.
- **통과 기준**: 담장 2~3m 구간에서 패널이 벽에 밀착되어 흔들림 없이 유지.
- **상태**: `PLANNED` · 실기기 검증 필수

## TV-03 — 건물 정합(실제 건물 ↔ 가상 장면) (04-B)
- **가설**: 지정 스팟에서 가상 건물/복원 요소를 실제 건물에 겹친다.
- **현실**: WebXR Chrome 안정판에 **이미지 추적(Image Tracking) 미탑재**. 건물 앵커 없음.
- **접근 후보(검증 대상)**:
  - (A) **이미지 마커/기준 이미지**: 스팟에 마커 또는 건물 특징 이미지 → 위치·방향 복원.
    WebXR 자체 Image Tracking이 없으므로 **별도 SDK 필요 가능**(예: 8th Wall, MindAR).
  - (B) **수동 정렬**: 사용자가 가상 모델을 드래그·회전·스케일로 실제 건물에 맞춤(가장 확실한 폴백).
  - (C) **스팟 고정 배치**: 스팟별 사전 측정된 상대 포즈 + Hit Test 바닥 기준.
- **필요 데이터(명시)**: 건물별 **기준 이미지 / 마커 이미지 / 스팟별 앵커(상대 포즈)**.
  → residence-16, residence-42(소제동), heredium(인동) 각각 필요.
- **통과 기준**: 지정 스팟에서 복원 요소가 실제 건물 윤곽과 체감상 정렬(사용자 보정 허용).
- **상태**: `PLANNED` · **SDK 채택 여부는 실기기 비교 후 결정**
- **상세 설계**: [`building-alignment.md`](./building-alignment.md) (4방식 비교, 권장 단계 전략,
  정합 검증용 임시 GLB 규격). 핵심 통찰: 미터 스케일 자동 일치로 실질 미지수는 **위치+yaw**.
  실제 건물 측량·사진 확보 전까지 **완료 보고 금지**.

## TV-04 — 역할극 벽 투시 연출 (06)
- **원칙**: 실제 벽을 투시하는 것이 **아님**. 가상 실내 장면 **합성**으로 구현.
- **접근**: 건물 위치에 가상 실내 공간 배치 + 벽 `WallDissolve`(투명화)로 내부 노출(포털 느낌).
  실제 가림(occlusion)은 depth-sensing 필요(미지원 기기 많음) → 기본은 비적용.
- **통과 기준**: 외부에서 바라볼 때 내부 장면·인물·대사가 끊김 없이 재생, 장면 종료 이벤트 반환.
- **상태**: `PLANNED`

## TV-05 — 광원 추정(light estimation)
- **접근**: 가능하면 적용, 미지원 시 에셋 emissive로 야간 가독성 확보(에셋 규격 §6).
- **상태**: `PLANNED`

## TV-06 — 실기기 성능 예산
- **접근**: 중급 Android에서 FPS/메모리 측정, 에셋 규격 §5 예산 조정.
- **상태**: `PLANNED`

## TV-07 — 브라우저/기기 호환성 매트릭스
- **접근**: Android Chrome(1순위) 실측. 기타(삼성 인터넷, iOS Safari=WebXR 미지원) 안내 처리.
- **통과 기준**: 지원 여부를 실제 기기로 확인한 표 작성. 추정만으로 "지원"이라 표기하지 않음.
- **상태**: `PLANNED`
