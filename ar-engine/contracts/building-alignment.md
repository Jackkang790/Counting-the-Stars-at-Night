# 건물 정합 기술 설계 (04-B) — 관사 16호 기준

> 상태: **설계(DESIGN) — 미구현 / 실제 건물 자료 확보 전**
> ⚠️ **실제 건물 측량·사진·기준 이미지가 확보되기 전에는 "건물 정합 완료"로 보고하지 않습니다.**
> 관련 리스크 추적: [`tech-validation.md` TV-03](./tech-validation.md).

## 1. 문제 정의와 핵심 제약

목표: **관사 16호**의 **지정 촬영 지점(spot)** 에서, 실제 건물 위에 가상 3D(복원/무대)를
**위치·회전·크기**가 맞게 겹친다.

핵심 제약(사실):
- **WebXR(Android Chrome 안정판)에는 건물 인식·이미지 추적 기본 기능이 없다.**
  Hit Test는 평면의 위치·방향만 제공하며 "이 건물이 관사 16호"라고 식별하지 못한다.
- 따라서 정합에는 **외부 기준 데이터**(스팟별 측량 포즈 / 마커 / 기준 이미지)가 필요하다.

**중요한 유리 조건 — 스케일:** ARCore 기반 WebXR은 **미터 스케일**로 추적한다. 에셋도
**1:1 미터**(Codex 규약)다. 따라서 **크기(scale)는 대체로 자동 일치**하고, 실질적으로
풀어야 하는 미지수는 **위치(3DoF) + 방위각(yaw)** 중심이다(지면이 평평하다는 가정 하에
roll/pitch는 중력 정렬로 안정적). 이 점이 정합 난이도를 크게 낮춘다.

## 2. 정합 좌표 정의 (공통)

- 가상 건물 모델: 원점 = **건물 정면 하단 기준점**(지면 `Y=0`), **정면이 `-Z`**(관람자/도로
  방향), 실척 1:1. (Codex 규약과 동일, [`asset-spec.md`](./asset-spec.md))
- 정합 = 월드좌표계에서 모델의 변환 `T(pos, yaw[, scale=1])`를 구하는 것.
- 스팟별 **기준점(reference points)**: 건물의 식별 가능한 실측 지점(예: 정면 좌/우 하단
  모서리)을 모델 로컬좌표로 정의 → 현장에서 이 점들을 맞추면 정합이 수렴.

## 3. 정합 방식 4종 — 구현 가능성·제약 비교

### (A) 수동 정렬 (Manual gizmo)
- 사용자가 화면 컨트롤로 모델을 **평면 이동 + yaw 회전**(+미세 스케일)해 실제 건물에 맞춤.
- **구현 가능성: 높음**(WebXR 기본만으로 가능, 외부 데이터 불필요).
- 제약: 사용자 수고/숙련에 따라 정확도 편차. 1인칭 원근에서 맞추기 난이도.
- 역할: **확실한 폴백 / 베이스라인**.

### (B) 스팟 고정 배치 (Spot-anchored, hit-test + 사전 측정 상대 포즈)
- 지정 촬영 지점에 사용자가 **서서 건물을 향하면**, 세션 시작 시 기기 포즈를 기준으로
  **사전 측정한 상대 포즈**(스팟→건물 기준점의 거리·방위·높이)를 적용해 자동 배치.
  바닥 높이는 Hit Test로 보정.
- **구현 가능성: 중간**(WebXR 기본 + 스팟별 측량 데이터).
- 제약: 사용자가 **정확한 지점·방향**에 서야 함. 초기 방위(yaw) 오차가 그대로 반영 →
  (A) 수동 미세조정과 병행 권장. 장시간 드리프트 가능.
- 필요 데이터: 스팟별 `{거리 d, 상대 방위 θ, 기준점 상대 위치}` 측량.

### (C) 이미지 마커 기반 (Marker, 물리 마커 + 카메라 프레임 CV)
- 스팟/건물에 **크기를 아는 마커(ArUco/QR)** 를 설치 → 카메라 프레임에서 마커를 검출하고
  `solvePnP`로 **마커 포즈**를 복원, 마커↔건물 고정 관계로 모델 배치.
- WebXR 자체 이미지추적이 없으므로 **`raw-camera-access`(실험적) + CV 라이브러리**(ArUco/
  jsQR+PnP) 필요, 또는 **상용 SDK**(8th Wall 등).
- **구현 가능성: 중간~낮음**(raw-camera-access 지원·성능, 조명/각도 민감, 설치 필요).
- 제약: `raw-camera-access`는 기기/버전 의존(가용성 검증 필요, [TV-03](./tech-validation.md)).
  마커 물리 설치·측량 필요. 야간 투어 조명 조건에서 검출률 리스크.
- 필요 데이터: 마커 이미지·실측 크기·건물 대비 설치 포즈.

### (D) 기준 이미지 기반 (Reference image / 자연특징 추적)
- 건물 **정면 사진(기준 이미지)** 을 타깃으로 자연특징 추적하여 포즈 추정.
- WebXR 네이티브 미지원. 실질적으로 **상용 SDK(8th Wall Image Targets 등)** 또는 자체
  특징매칭/SLAM 필요(브라우저 실시간은 난도 높음).
- **구현 가능성: 낮음(순수 WebXR)**, SDK 도입 시 중간(비용·종속성 발생).
- 제약: 라이선스·비용, 외부 SDK 종속(WebXR 파이프라인 교체 가능성), 야간/가변 조명·
  계절 변화로 기준 이미지 불일치.
- 필요 데이터: 고품질 정면 기준 이미지(촬영 조건별 다수 가능).

## 4. 권장 단계적 전략

1. **1단계(기본):** (B) 스팟 고정 + (A) 수동 미세조정 — WebXR 기본만으로 즉시 구현 가능,
   외부 데이터 최소. 실제 건물 자료(스팟 측량) 확보 시 정밀도 상승.
2. **2단계(강화):** (C) 마커 — `raw-camera-access` 가용성·검출 성능을 실기기로 검증 후 채택
   여부 결정. 가능하면 자동 정합으로 수동 수고 제거.
3. **3단계(선택):** (D) SDK 기반 기준 이미지 — 비용/종속 트레이드오프 평가 후.

> 어떤 단계도 **실제 건물 측량/사진 확보 + 실기기 검증** 전에는 "완료"로 보지 않는다.

## 5. 위치·회전·크기 일치 방법 (정합 수렴 절차)

1. 세션 시작 → Hit Test로 **지면(Y=0)** 확보(높이·중력 정렬).
2. 초기 배치: (B) 스팟 상대 포즈 또는 (C) 마커 포즈로 `T(pos, yaw)` 설정.
3. **스케일 = 1.0 고정**(미터 스케일 자동 일치, 사용자 스케일 조정은 보조만).
4. 사용자 **수동 미세조정**(이동/yaw)으로 기준점 2점(정면 좌/우 하단 모서리)을 실제와 일치.
5. 정합 품질 지표(선택): 기준점 투영 오차를 화면에 표시해 수렴 보조.

엔진 API(예정): `beginAlignment()`, `nudge({dx,dz,dyaw})`, `confirmAlignment()` +
`alignmentChanged` 이벤트. (현 프로토타입 미구현 — 설계만.)

## 6. 현장에서 확보해야 할 데이터 (관사 16호)
- 지정 촬영 지점(spot)별: 위치, **건물 기준점까지 거리·방위**, 지면 높이차.
- 건물 **정면 실측 치수**(폭·높이·기준점 모서리 좌표) — 모델 원점/스케일 확정용.
- (C 채택 시) 마커 설치 위치·크기·건물 대비 포즈.
- (D 채택 시) 정면 기준 이미지(촬영 조건별).
- 복원 대상(사라진 부분) 고증 자료(사진·도면).

## 7. 정합 검증용 임시 GLB 에셋 규격 (최초 제안 — 참고용, 실제는 §6-A)

실제 건물 자료 확보 전, **정합 파이프라인을 검증**하기 위한 **임시 캘리브레이션 에셋**.

- **id(예)**: `residence16_align_calib` · **category**: `building_stage` ·
  **status**: `provisional_concept`(실측 아님 명시).
- **좌표/단위**: 1:1 m, Y-up, 정면 `-Z`(기존 규약).
- **기준점 노드**: `ANCHOR_Ground` = **건물 정면 하단 기준점**(지면 Y=0).
- **형상(검증 보조용, 실측 전 임시 치수 — 매니페스트에 임시임을 명시):**
  - 반투명 **건물 박스/와이어프레임**(관사 16호 추정 footprint·높이 placeholder).
  - **지면 footprint 사각 외곽선** + **모서리 포스트 4개**(기준점 가시화).
  - **정면 방향(+? → -Z) 화살표** 1개(정면 식별).
  - **1m 스케일 참조 큐브** 1개(스케일 검증).
  - (선택) `PAST_*`/`PRESENT_*` 그룹으로 과거↔현재 토글 검증.
- **클립**: 정적 중심. 선택 `Reveal`(등장), `RestoreIn`(복원 요소). 접두사 없음(`AR_`도 호환).
- **매니페스트 확장 필드(제안)** — 정합 기준점:
  ```jsonc
  "calibration": {
    "reference_points": [
      { "name": "front_left_base",  "local_m": [-x, 0,  z] },
      { "name": "front_right_base", "local_m": [ x, 0,  z] }
    ],
    "facade_size_m": { "width": 0.0, "height": 0.0 },   // 실측 전 0/placeholder
    "provisional_dimensions": true
  },
  "time_phase": { "enabled": true }
  ```
- **예산**: 박스/와이어 중심이라 경량 가능 → 기존 예산(≤12k tris, ≤1.5 MB) 내 목표.
  실제 복원 모델은 규모상 별도 예산 협의([`asset-spec.md` §3.4](./asset-spec.md)).
- **GLB 포함 금지**: depth occlusion, 지면 그림자 평면, 렌더 전용 카메라/광원(기존 규약).

> 이 임시 에셋은 **실측 치수가 아님**을 `status`/`provisional_dimensions`로 명시한다.
> 실제 측량 확보 후 치수·기준점을 교체한다.

## 8. 검증 계획 (→ TV-03)
- 캘리브레이션 에셋으로: (B) 스팟 포즈 + (A) 수동 정렬 흐름을 **실기기**에서 점검.
- `raw-camera-access` 가용성 실측 → (C) 채택 가능성 판단.
- 통과 기준: 지정 스팟에서 기준점 2점이 실제 건물과 체감 정렬(사용자 보정 허용),
  드리프트 허용 범위 확인. **실제 건물 자료 확보 + 실기기 검증 전까지 미완료.**
