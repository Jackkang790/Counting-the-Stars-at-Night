# 공간형 실사 공연자 구현과 3D 캡처 시퀀스

현재 시연 URL은 `?musical=1`이다. 기존 별의 새싹·외벽 정합과 빌드 설정은 유지한다. 새 공연에는 건물 로컬 좌표에 배치된 `PerformerSlot`을 사용하며, 영상 평면과 동적 3D 프레임을 같은 슬롯에서 교체한다.

## 구현 단계

| 단계 | 현재 구현 | 실제 콘텐츠·기기 검증 상태 |
| --- | --- | --- |
| 1 공간 고정 실사 AR | 알파 영상이 THREE.PlaneGeometry에 적용되고 건물 앵커 아래에 고정. 카메라를 따라 도는 빌보드 동작 없음 | 허용된 스톡 인물 2명 포함. 완전한 입체 인물이 아님. 실제 폰 검증 필요 |
| 2 입체 실사 로더 | 시점에 따라 다른 면이 보이는 비평면 GLB 프레임 시퀀스 로드·재생. 영상 평면·동일 정적 형상 반복은 거부 | 실제 인물의 볼류메트릭 캡처 미제공. 인물이 아닌 3D 도형으로 로더 검증 |
| 3 연출 통합 | 두 표현 방식이 같은 30초 AudioContext 타임라인·등장/퇴장·조명·파티클·건물 정합을 사용 | 최종 안무·음원·실측 및 기기별 동기는 현장 검증 필요 |

3D 로더가 있다는 사실을 실제 지역 공연자의 볼류메트릭 공연이 완성됐다는 뜻으로 표시하지 않는다. `source.kind`는 제공자가 선언하는 출처이며 실사 여부를 자동 인증하지 않는다.

## 공간 연결

```text
추적 기준 (WebXR 월드 포즈 또는 인식된 이미지 포즈)
└─ 기존 PlacementGroup 규칙의 정합 변환
   └─ MusicalStageRoot
      ├─ 건물 렌더링·깊이 모델·효과
      ├─ ANCHOR_door_actor-a
      │  └─ PERFORMER_actor-a       ← 개별 위치·회전·크기, 표현 교체 시 유지
      │     └─ 영상 평면 또는 현재 3D 캡처 프레임
      └─ ANCHOR_panel_actor-b
         └─ PERFORMER_actor-b
            └─ 영상 평면 또는 현재 3D 캡처 프레임
```

두 공연자는 DOM 또는 카메라의 자식이 아니다. `mountSpatialPerformer()`가 건물 앵커에 배치하고 `spatialSnapshot()`은 카메라 연결 여부와 건물 상대 행렬을 기록한다. 시점이 바뀌거나 모델 프레임이 재생되어도 외곽 슬롯의 건물 상대 행렬은 변하지 않는다. 인물의 동작은 슬롯 안의 로컬 기하만 바꾼다.

WebXR에서는 월드 참조 공간과 카메라 이동을 이용한다. 공통 이미지 추적 경로에서는 기기에 대한 건물 포즈가 바뀌므로 카메라 기준의 숫자도 바뀔 수 있지만 공연자와 건물의 상대 변환은 유지한다. 표적을 잃으면 무대를 숨기고 음원·재생을 정지한다. 이 경로를 표적 밖에서도 유지되는 영속 SLAM이라고 설명하지 않는다.

기존 엔진의 미터·Y-up·-Z 정면 규약과 `PlacementGroup`을 재사용한다. 이전 Quick Look 세션의 네이티브 월드 앵커를 웹으로 가져오거나, 종료된 WebXR 세션의 원점을 자동 승계하는 기능은 아니다. 새 공연 경로에서 벽을 다시 정합하고 그 활성 좌표계 안에서 건물과 두 공연자의 변환을 공유한다. 기존 외벽 모델의 월드 포즈를 자동 이관했다고 주장하지 않는다.

가림은 기존 분리된 기둥 depth-only 모델과 depth test로 수행한다. 모델은 임시 치수라 기본 비활성이며, 실측에 맞춘 후 켠다. 영상 평면은 신체의 깊이가 하나이므로 팔·몸의 부분 가림이나 옆·뒤 모습이 정확하지 않다. 3D 시퀀스는 실제 기하를 깊이 검사하지만 실제 벽 치수가 틀리면 가림도 틀린다. 현실 공간의 자동 depth reconstruction은 추가하지 않았다.

## 3D 시퀀스 입력

개발자 패널에서 배우별 `.vseq.json` 한 개와 참조하는 모든 GLB를 함께 선택한다. 파일은 서버로 업로드하지 않는다. 각 GLB는 **같은 미터 좌표·같은 발 접지 원점에서 캡처한 시점별 정적 3D 형상**이어야 한다. 프레임마다 크기를 정규화하거나 원점을 다시 맞추지 않는다.

```json
{
  "version": 1,
  "type": "volumetric-mesh-sequence",
  "units": "meters",
  "up": "+Y",
  "front": "-Z",
  "origin": "ground-center",
  "fps": 12,
  "source": {
    "kind": "human-capture",
    "title": "공연자 A의 실제 3D 캡처",
    "license": "제공자의 이용 허락·출연 동의에 대한 실제 정보"
  },
  "frames": ["frame-000.glb", "frame-001.glb"]
}
```

위 JSON은 형식 예시이며 실제 인물 캡처 파일은 포함하지 않는다. 최대 900프레임, 1~30fps, 배우당 입력 합계 48MiB·추정 디코딩 리소스 48MiB·프레임당 100,000삼각형으로 제한한다. 모든 프레임을 사전 로드하는 MVP이며 대용량 스트리밍 로더는 아니다. 단일 scene, 내장 버퍼/텍스처를 사용한다. Draco/Meshopt/KTX2 디코더와 프레임 내부 본·모프 애니메이션은 지원하지 않는다. 캡처를 프레임별 정적 GLB로 베이크해야 한다.

입력은 3차원으로 펼쳐진 비평면 정점과 서로 다른 시간 형상을 검사한다. 평면 GLB를 돌려 놓거나 같은 정적 메시를 반복하는 방식은 거부한다. 이것은 실제 사람이라는 의미 검증을 대신하지 않는다. 세부 모델 품질·연기·시점별 외형은 촬영본과 실기기로 확인해야 한다.

`PerformerSlot.loadSequence()`는 파일 판독 어댑터를 받아 동일한 형식의 사전 배포 데이터도 로드할 수 있다. 현재 샘플은 Vite URL로 묶이며 기존 public 모델 스테이징 목록을 수정하지 않는다. 메모리 상한을 넘는 고해상도·장시간 캡처에는 후속 스트리밍/전용 코덱 구현이 필요하다.

## 로더 시연

1. 공연 화면에서 **개발 무대 미리보기**를 연다. 이 화면은 실제 AR이 아니다.
2. 개발자 패널의 **3D 시퀀스 로더 검증 — 도형·실사 인물 아님**을 누른다.
3. 공연 준비에서 **3D 도형 기술 테스트**를 실행한다. 기존 30초 타임라인의 5초와 10초에 각 3D 객체가 등장하고 캡처 프레임이 순환한다.
4. 정지한 후 **미리보기 왼쪽/정면/오른쪽**으로 면·깊이·시점 차이를 확인한다. 진단을 저장하면 건물 상대 행렬과 현재 3D 프레임 번호를 볼 수 있다.
5. 실사 샘플을 다시 불러오면 같은 위치·회전·크기에서 영상 평면으로 돌아간다. 도형은 실사 공연 시작 버튼으로 재생하지 않는다.

실제 AR에서도 같은 슬롯과 타임라인을 사용한다. 스마트폰을 움직여 시험하며 미리보기 시점 버튼을 실제 기기 추적으로 취급하지 않는다. 배우별 등장 시각은 개발자 패널에서 조절할 수 있다.

## iPhone 경로

기존 iPhone Quick Look 링크와 USDZ 내보내기는 보존한다. Quick Look이 USDZ의 애니메이션을 지원한다는 사실만으로 웹 VideoTexture나 이 사용자 정의 프레임 플레이어를 그대로 실행한다고 가정하지 않는다. 새 영상·3D 시퀀스는 Three.js의 공통 이미지 추적 경로에서 실행하고 Android는 추가 WebXR 경로도 제공한다. [Apple Quick Look 설명](https://developer.apple.com/quick-look-gallery/)

이 구현은 현재 설치된 Three.js 0.169.0의 GLTFLoader를 재사용한다. 라이브러리·원래 엔진·기존 에셋을 업그레이드하지 않는다. [Three.js GLTFLoader](https://threejs.org/docs/#GLTFLoader)

## 검증과 남은 작업

`node tests/spatial-volume-unit.mjs`는 실제 GLB 로드·프레임 변화·평면/정적 반복 거부·카메라 이동 시 건물 상대 좌표 보존을 검사한다. 브라우저 검사는 렌더러 교체·프레임 재생·다른 시점·3D 도형의 실사 오인 방지를 확인한다. 기존 AR 보호 검사와 30초 실사 영상 검사도 유지한다.

브라우저 재검증은 `MUSICAL-MVP.md`의 임시 Playwright 설치 후 실행한다. URL은 첫 번째 인자로 바꿀 수 있다.

```powershell
node tests/musical-unit.mjs
node tests/spatial-volume-unit.mjs
node tests/spatial-volume-browser.mjs https://localhost:5187/
node tests/musical-browser.mjs https://localhost:5187/
```

실제 인물의 볼류메트릭 데이터, 실제 벽의 실측, 갤럭시·iPhone에서 이동·가림·발열·동기를 확인하기 전에는 최종 입체 실사 AR 공연이 검증됐다고 표시하지 않는다.
