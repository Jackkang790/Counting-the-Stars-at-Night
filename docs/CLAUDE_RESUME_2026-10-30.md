작업 시작 시 확인 기준: 통합 브랜치 `81354f1`, 당시 서버 `current-tour/release.json`도 같은 커밋이었다. 작업은 별도 `fix/near-stage-unified-ui` 브랜치에서 진행한다.

- 별도 `.worktrees/unified-tour`에는 프론트/AR/REST 통합, 같은 origin의 `/ar/` 경로, 공연 완료 메시지·별 지급 검증, 영속 API/롤백 배포가 커밋돼 있다.
- `0087203`에는 2m 최소 거리 제거, 가까운 무대 축소, 노란 바닥 후보/버튼, 탭 후 공연 시작이 이미 구현돼 있었다. `81354f1`에는 배포 이미지 재사용/고정이 들어 있다. 두 작업을 없애고 처음부터 다시 만들지 않는다.

## 확인된 남은 문제와 이번 수정

- 가까운 바닥을 내려다볼 때 기존 크기 계산은 수평 거리만 사용한다. 실제 투영에서 네 배우가 들어오는 크기를 계산하고 배치할 때 한 번만 적용한다. 휴대폰 이동으로 배치된 무대가 따라오거나 자동 확대/축소되지 않는다. 배치 후 별도 크기 조절은 앵커를 옮기지 않는다.
- 노란 표시 밖을 눌러도 다른 특징점에 배치되는 경로를 4인 공연에서 막았다. 실제 hit/유효 추적이 없으면 표시/배치를 만들지 않는다. SLAM의 특징점은 실제 바닥 평면 분할의 보장이 아니며 WebXR hit-test와 구분한다.
- iframe 바깥 프론트와 안쪽 AR 헤더/큰 제어판이 중복됐다. 같은 origin의 iframe에 프론트 색·글꼴 토큰을 전달하고, 안쪽 헤더를 숨겼다. 작은 조작부를 제외한 나머지 영역을 카메라와 바닥 선택 표시가 같이 사용하므로 제어판이 바닥 버튼을 가로막지 않는다. 공연 전 불필요한 보상 버튼 공간은 숨긴다. 완료 검증/별 지급의 조건은 유지한다.
- 관객 제어는 시작·일시정지·다시 보기·촬영·바닥 재선택·크기 조절만 남긴다. 기존 개발 도구는 `?debug`로 보존한다. 별의 새싹도 같은 임베드 테마를 사용하며 기존 Quick Look 경로를 바꾸지 않는다.

## 검사

`npm run build`, `npm run lint`, `node tests/stage-fit.mjs`, `node tests/floor-placement-browser.mjs http://localhost:8193`, `node tests/integration-browser.mjs http://localhost:8193`을 사용한다. 0.35m/0.8m 후보, 표시 밖 터치 차단, 크기 변경과 카메라 이동 시 앵커 유지, 프론트 테마 전달, 완료 전 보상 차단/잘못된 메시지 차단을 확인한다.

브라우저 AR 입력은 모의 추적이다. 실제 iPhone/Android의 바닥 인식·드리프트·성능을 검증했다고 표시하지 않는다. 배포는 기존 `deploy/activate.sh`를 사용하며 제작 서비스·DB를 보존한다.

## 배포 결과

코드 `185c3fe`를 `unified-185c3fe-da2fb8938815`로 반영했다. [공개 앱](https://ar.lobodoc.com/?v=185c3fe#roleplay/h1)에서 공연 버튼으로 진입한다. 공개 파일 해시, 단일 상단바, 프론트 테마 전달, 닫기, REST/제작 API 상태와 근거리 모의 추적 검사가 통과했다. 상세 기록은 `docs/ar-ui/deployment.json`, `public-floor.json`, `validation.json`이다. 스크린샷 파일의 `mock` 표시는 실제 카메라 촬영 사진이 아니라는 뜻이다.

최초 배포는 디스크 여유 사전 검사에서 멈췄다. 로컬 보관본과 SHA256이 같은 이전 임시 업로드 ZIP 세 개만 정리한 뒤 정상 배포했다. 현재 릴리스/이전 릴리스/DB 백업/제작 서비스는 삭제하지 않았다. 백엔드는 변경되지 않은 이미지를 재사용했고 기존 데이터는 유지했다.
