# 외벽 정합 테스트 에셋 — 제작 계획 및 Claude 인계 규격

작성 순서: 이 제작 계획과 전달 규격을 먼저 기록한 뒤 구현했다. ID `alignment_test_facade`, 버전 `0.1.0`. 현재 합성 에셋 생성·렌더·파일 검증은 완료했으며 현장/엔진/모바일 검증은 미완료다.

## 목적과 범위

실제 건물 외벽에 가상 건축 요소를 맞추는 기술을 검증할 **합성 시험물**이다. 아래 모든 치수는 시험 편의를 위해 정한 값이며 관사 16호·관사 42호·헤레디움의 실측이나 재현이 아니다. 현장에서는 외벽/문/창 크기를 이 값으로 가정하지 않는다. 실제 대응점을 측정하거나 이 규격의 시험판/모형과 비교해야 한다.

기존 `feature/blender-assets` worktree에서만 문서·스크립트·원본·결과를 생성한다. 공유 루트와 `ar-engine/`에 복사하지 않는다. 공통 계약 파일 및 기존 `asset-manifest.json`, 별의 새싹 에셋을 변경하지 않는다. Blender 실행 파일은 기존 설치본을 읽기 전용으로 재사용할 수 있으며 런타임 캐시는 해당 worktree의 `blender/.tools/`에 둔다.

## 제작 순서

1. 이 문서로 치수·레이어·좌표 계약을 기록한다.
2. bpy로 창·문 구멍을 가진 외벽, 창호·문, 기준점 표시, 격자, 반투명 건축 요소를 생성한다.
3. 정적 장면으로 `.blend`와 GLB 2.0을 저장한다. 좌표를 흔드는 애니메이션은 포함하지 않는다.
4. 정면·사선·반투명 오버레이 단독 렌더와 GLB 재수입 렌더를 생성한다.
5. Blender 원본 재열기, GLB 바이너리·기준점·단위·재질·투명도·메시 예산, Khronos 및 Three.js 로더 검사를 실행한다.
6. 관측한 크기·삼각형·정점·재질·해시·검증 결과를 전용 매니페스트에 기록한다. 별의 새싹 파일 불변과 worktree 범위를 확인한다.

## 합성 형상 규격

| 항목 | 시험 치수 |
|---|---|
| 외벽 기준물 | 폭 6.00m × 높이 3.60m × 두께 0.20m |
| 외벽 정면 | GLB Z=0, 외벽은 Z=0..+0.20m 방향으로 두께를 가짐 |
| 문 구멍 | X=-0.50..+0.50m, Y=0..2.20m |
| 왼쪽 창 구멍 | X=-2.35..-1.15m, Y=1.15..2.45m |
| 오른쪽 창 구멍 | X=+1.15..+2.35m, Y=1.15..2.45m |
| 격자 | 0.50m 간격, 1.00m 주눈금, 원점 근처 0.20m 길이의 0.01m 보조 눈금 |
| 투명 오버레이 | 창/문 테두리와 상부 띠장. alpha 0.28, GLB BLEND |

기준물 자체와 디버그 메시의 AABB는 구분한다. 기준점 표시는 모서리 바깥/지면 아래로 소량 확장될 수 있으며 전체 크기는 실제 내보낸 AABB를 기록한다. 배치 원점은 외벽 정면의 바닥 중앙이다.

## 좌표 계약과 기준점

- GLB 2.0, 1 unit=1m, 오른손 좌표계, +Y 위, **-Z 정면**.
- Blender는 +Z 위, +Y 정면. Blender `(x,y,z)` → GLB `(x,z,-y)`.
- 루트 `ANCHOR_Facade` = GLB `(0,0,0)`, 외벽 정면 바닥 중앙. 자동 중심 보정 금지.
- 아래 기준점은 모두 루트 기준 **미터 단위 GLB 로컬 좌표**이며 외벽의 수학적 기준면 Z=0 위에 있다. 마커 메시의 표면 위치가 아닌 빈 노드의 원점을 정합에 사용한다.

| 노드 | 의미 | GLB [X,Y,Z] m |
|---|---|---|
| `PT_P00_Origin` | 원점 | [0, 0, 0] |
| `PT_P01_WallBL` | 외벽 좌하단 | [-3, 0, 0] |
| `PT_P02_WallBR` | 외벽 우하단 | [3, 0, 0] |
| `PT_P03_WallTL` | 외벽 좌상단 | [-3, 3.6, 0] |
| `PT_P04_WallTR` | 외벽 우상단 | [3, 3.6, 0] |
| `PT_P05_DoorTL` | 문 좌상단 | [-0.5, 2.2, 0] |
| `PT_P06_DoorTR` | 문 우상단 | [0.5, 2.2, 0] |
| `PT_P07_WindowLBL` | 왼쪽 창 좌하단 | [-2.35, 1.15, 0] |
| `PT_P08_WindowLTR` | 왼쪽 창 우상단 | [-1.15, 2.45, 0] |
| `PT_P09_WindowRBL` | 오른쪽 창 좌하단 | [1.15, 1.15, 0] |
| `PT_P10_WindowRTR` | 오른쪽 창 우상단 | [2.35, 2.45, 0] |

관람 방향에서 -Z를 바라보는 모델의 좌우와 사진의 좌우는 촬영 방향에 따라 다르므로 노드명보다 좌표를 우선한다. 사진상의 점 순서와 GLB 대응점 순서를 명시해 전달한다. 전부 같은 평면에 있는 점이므로 독립적인 깊이 기준이나 추적 마커 검출 기능을 제공하지 않는다.

## 레이어 및 엔진 사용법

| GLB 그룹 | 내용 | 실건물 합성 시 |
|---|---|---|
| `REFERENCE_Facade` | 합성 외벽·창·문 | 숨김; 불투명 기준물이 실제 카메라 영상을 가리지 않게 함 |
| `CALIBRATION_Markers` | 기준점의 시각적 십자/체커 표시 | 필요 시 표시 |
| `CALIBRATION_Grid` | 0.5m 격자와 1cm 보조 눈금 | 필요 시 표시 |
| `OVERLAY_Architecture` | 반투명 창/문 테두리와 상부 띠장 | 표시 |
| `POINTS_Facade` | PT_* 빈 노드 11개 | 좌표 취득; 렌더 메시 없음 |

격자/시각 마커/오버레이는 Z-fighting 방지를 위한 작은 **-Z 방향 레이어 간격**을 가진다. 각 간격은 매니페스트에 기록한다. 이 간격을 정합 오차로 계산하지 말고 PT_* 노드와 기준면 Z=0을 사용한다. 반투명 오버레이의 실제 시야/정렬은 카메라 위치에 영향을 받는다.

GLB를 별도 배치 Group으로 감싼 뒤 그 Group에만 정합 변환을 적용한다. `PT_*`의 `getWorldPosition()`은 부모 변환을 반영하므로 로컬 기준값과 월드 관측값을 혼용하지 않는다. 기준점이 정적이므로 애니메이션 클립 목록은 빈 배열이다.

마커 모양은 눈으로 확인할 표시이며 QR/AprilTag/ArUco 검출용 패턴으로 인증되지 않았다. 자동 인식, 카메라 자세 추정, 건물 인식, GPS는 엔진 담당 범위다.

## 전달 파일과 예산

- `public/models/alignment_test_facade.glb`
- `public/models/alignment_test_facade.manifest.json`: 독립 에셋 메타데이터 + 기준점/레이어 정의. 공통 카탈로그에는 자동 추가하지 않는다.
- `blender/scenes/alignment_test_facade.blend`
- `blender/scripts/build_alignment_facade.py`, 검증 스크립트와 실행용 PowerShell
- `blender/renders/alignment_*`, `blender/reports/alignment_*`
- 정합용 모델의 내부 예산: ≤8,000 tris, ≤12,000 exported vertices, ≤16 primitives, ≤1MB GLB, 텍스처 0개. 불투명/반투명 재질을 별도 메시로 분리한다.

Three.js 실제 로더·표준 PBR/BLEND·레이어 전환·기준점의 배치 Group 변환을 검증한다. 웹 브라우저/모바일 GPU의 alpha 정렬, 현장 추적 정확도, 실제 건물과의 정합 오차, 기기 FPS는 별도 실기기 검사이며 이번 에셋 검증만으로 통과를 주장하지 않는다.

## 제작 후 관측 결과

- Blender 4.5.15 LTS에서 생성·내보내기·원본 재열기·GLB 재수입 성공.
- 전체 geometry: 1,812 tris, 3,624 exported vertices, 11 primitives, 8 materials, 108,412 bytes.
- 전체 AABB: min `[-3.08,-0.075,-0.054]`, max `[3.08,3.68,0.20]`m. 바닥 아래 7.5cm는 모서리 디버그 마커의 절반이며 기준 외벽은 Y=0에서 시작한다.
- Blender/바이너리/재수입/렌더 비교 111건, Three.js r186 로더/레이어/배치 변환 검사 38건 통과. Khronos 오류·경고 0건.
- Cycles 원본 3장 + GLB 재수입 2장 생성. 정면/오버레이 원본-재수입 RGB RMSE는 각각 약 0.0000251 / 0.0000135 (허용 0.025).
- `blender/reports/alignment_scope.json`에 worktree·기존 에셋 불변·공유 루트 미복사 확인을 기록했다.
